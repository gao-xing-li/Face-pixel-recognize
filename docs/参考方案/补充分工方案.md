# 实验3：基于颜色信息的亚洲人脸分割

> 历史参考：本文保留早期分工方案或对比时的内容，不代表当前实现状态。当前 A 分支的数据、职责边界与目录以 [Part A 设计与决策记录](../PartA设计与决策记录.md) 和项目 README 为准；其中默认算法、参数与目录示例不自动成为当前决定。

## 小组分工与实验设计

### 一、实验目标与基本路线

根据实验题目，利用颜色信息对亚洲人脸进行分割，并在多幅人脸图像上验证效果。以肤色作为主要分割依据，展示分割结果，分析误检、漏检及方法的适用条件。

基础路线为：准备图像与标签 → 统计肤色分布 → 建立颜色阈值规则 → 在验证集上选择参数 → 使用固定方案测试 → 汇总结果与报告。

以 **YCbCr 颜色空间和肤色均值、方差统计**作为优先方案。具体颜色分量、统计方式和基础判别建议由成员 A 处理；成员 B 根据验证结果确定实际使用的参数与规则。主要使用 Python、OpenCV、NumPy、Matplotlib。

采用一套由训练集建立、验证集调好的模型处理测试图像，不针对每张测试图像重新采样或单独调参。

### 二、实施范围与推进顺序

**先完成基础版本，再按实际效果补充辅助处理。** 基础版本应能够完成肤色统计、阈值分割、二值掩膜输出和效果评价，先形成可运行的完整流程。

允许参考工业界、学术界已有的颜色人脸分割方法，按需要加入图像预处理、形态学处理、连通区域筛选、形状约束或模板过滤等辅助方式。上述方式是可选方向，不要求全部实现，也不要求完整复现某篇论文。辅助方法的调研和实现不阻塞基础版本。

辅助处理主要由 B 根据失败案例、验证效果和实现时间选择。A、C 可以提供资料或改进建议。保留基础版本结果，便于说明辅助处理带来的变化。实验以颜色方法为核心，不把深度学习或复杂人脸检测系统作为本次工作的目标。

### 四、各部分可以自行决定的事项

**A 自行决定数据和统计细节。** Pratheepan 可作为候选数据集，是否采用、如何选择样本、是否补充或替换数据，由 A 根据题目匹配程度、标签可用性和准备成本判断。UCI Skin Segmentation 如有需要可辅助像素统计，但多幅图像的分割验证仍需准备实际图片。

A 可以提供额外的通道统计或候选参数，供 B 选择使用；同时应给出一个能直接运行的默认建议，不以准备所有候选结果作为交付前提。不要求为了比较而系统遍历多个颜色空间或多套模型。

**B 自行决定验证与调参细节。** 包括阈值系数的候选范围、选参指标、是否增加辅助处理，以及最终使用哪些统计结果。B 可以使用 AI 辅助编写调参评价程序，不依赖 C 先完成评价模块。

**C 自行决定测试分析和报告组织细节。** 根据最终方案组织指标、案例与分析。评价程序可以自行实现，也可以复用 B 的代码；同名指标的定义、标签含义和计算口径应保持一致。

具体文件组织、内部函数、绘图样式等由各部分负责人决定。涉及其他部分输入输出的变化，及时说明即可。

### 五、协作流程与交接

**1. 数据与基础流程准备**

A 优先提供可用样例、数据划分和基础统计结果。B、C 可先准备各自的程序框架与评价流程，使用少量样例检查能否接通。

A 向 B 说明实际使用的颜色转换、通道、统计参数含义及默认用法；数据清单和标签含义同时提供给 B、C。数据读取和预处理约定应保证建模与检测一致，无须在开工前固定所有接口细节。

**2. 验证与方案确定**

B 先跑通基础版本，在验证集上选择参数。基础流程稳定后，再根据需要查找、尝试辅助方式，并比较效果。B 保存最终采用的参数、处理步骤和运行方式，交给 C。

**3. 独立测试与分析**

C 使用确定后的方案处理测试集，记录指标并分析结果。测试集不参与参数选择；若根据测试结果继续修改方案，应将相关图像视为参与了开发，并另行安排独立测试。

评价可采用 Accuracy、Precision、Recall、F1-score 等指标，并结合分割效果图解释结果。B 决定验证选参依据，C 在交接时核对评价口径。条件差异的分析以实际图像和实验结果为依据，不要求额外展开大规模实验。

**4. 成果与报告整合**

每位成员提交自己的代码、图表、分析和对应报告内容。B 负责最终代码整合，C 负责最终报告整合，其余成员配合核对，保证参数、图表、指标与文字一致。

三位成员可使用 Codex 等 AI 工具辅助完成各自任务，负责人核查实现与结果。
